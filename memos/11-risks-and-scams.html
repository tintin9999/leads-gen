Risks & Scams: Don't Get Burned

The threats that hit solo developers in 2025–2026: malware hidden in fake interviews, payment and task scams, platform fraud, ID phishing, unpaid work, legal traps from your last job, data and credential leaks, and burnout. For each one: how it looks, what to watch for, how to prevent it, and what to do if it happens.

Bottom line. A new freelancer is the ideal target: eager, short of cash, and saying yes to strangers. That's when people get scammed. Two habits stop most of the damage. (1) Never run a stranger's code or command on your main machine. Fake "clients" and "recruiters" send repos or setup commands that install backdoors and steal your keys, wallets and client credentials. A documented North Korean campaign has done this to developers since 2022 and is still running in 2026. (2) Money only moves one way, on paper. Clients pay you, from their own account, against a signed agreement and your invoice. You never pay to get work, never refund an "overpayment", and never take payment from a third party. Everything else here, from NDAs and licences to burnout, is about protecting the business you're building.

2. Malware hidden in fake interviews, clients and "take-home" tasks#

This is the threat aimed most directly at you. Microsoft's March 2026 analysis describes the Contagious Interview campaign, which has been active since at least December 2022. It runs "convincingly staged recruitment processes" with recruiter outreach, technical discussions and assignments. Victims are told to clone and run an npm package from GitHub, GitLab or Bitbucket, or to open a repo in VS Code and trust the author. The repo's task file then fetches a backdoor (BeaverTail/InvisibleFerret, OtterCookie, and newer variants). The malware hunts for .env files, wallet seed phrases, password-manager databases, SSH keys and other secrets. Attackers pose as recruiters from crypto trading firms or AI startups. They now pose as freelance clients too: "can you review/fix our repo?" Separately, a 2025 variant ("ClickFake Interview") shows a fake camera/microphone error during a video interview and asks you to paste a "fix" command into your terminal. And npm worms like Shai-Hulud (Sept and Nov 2025) used install scripts to steal npm/GitHub/cloud tokens and republish themselves into the victims' other packages.

How it looks

A LinkedIn/Telegram recruiter or "client" with a crypto, Web3 or AI product and an unusually good rate. A repo (often a "blockchain game" or "MERN dashboard") to "run locally and fix a bug" before a call. A meeting link that needs a special app or a "driver fix". Time pressure: "the CTO is waiting".

Red flags

New GitHub/Bitbucket account or repo. Short links redirecting to file hosts. Setup steps that are oddly complex. package.json with preinstall/postinstall scripts or obfuscated one-liners. A .vscode/tasks.json with "runOn": "folderOpen". Requests to disable antivirus or "trust the authors". Any "paste this command to fix your camera".

Prevention

Run unknown code only in a disposable VM or container with no credentials (SOP below). In VS Code set "task.allowAutomaticTasks": "off" and keep Workspace Trust on (open unknown folders in Restricted Mode). Read package.json scripts and .vscode/ before anything else. Never paste terminal commands from a website or a stranger. Keep crypto wallets off your work machine entirely.

If it happens

Follow the incident playbook: disconnect, then from a clean device rotate email, GitHub, npm, cloud and client credentials, revoke SSH keys and tokens, move any crypto, tell affected clients, and reinstall the OS. Report it at cybercrime.gov.in. As a CTF player you know the drill: assume full compromise.

3. Safe-sandbox SOP for untrusted client code#

Use this for every repo, archive or installer from someone who hasn't signed a contract and paid a deposit, and for take-over projects ("our last dev left") until you've read the code. It takes about 10 minutes and protects your whole business.

  1. Read first, run never (yet). Browse the repo on GitHub/GitLab in the browser, or clone it somewhere you won't open in an IDE. Check account age, commit history and stars. One commit with "initial" from a 2-week-old account is a warning sign.
  2. Inspect the auto-run surfaces. package.json → scripts (especially preinstall, install, postinstall, prepare); .vscode/tasks.json, .vscode/settings.json, .devcontainer/; Makefile, *.sh, .husky/; files with odd extensions (a .woff or .png that's actually JavaScript); long base64 or obfuscated strings; eval, new Function, child_process, curl | sh.
  3. Use a disposable environment. A VM (UTM or Parallels on Mac, Hyper-V or VirtualBox on Windows, Multipass on Linux) or a container. It must have no SSH keys, cloud CLIs, password manager, browser sessions, wallets or client folders. Snapshot the VM before you start and roll back afterwards.
  4. Install without scripts. npm ci --ignore-scripts (or npm install --ignore-scripts). pnpm v10+ already skips dependency build scripts unless they're allow-listed. Then run npm audit and look at what's actually installed.
  5. Be careful with the network. For the first run, prefer no network or a restricted one. Watch for unexpected outbound connections. Never mount your home directory into the container.
  6. Separate identities. Use a separate OS user or browser profile per client. Don't log into your personal GitHub, email or bank inside the sandbox.
  7. Only after a contract + deposit does the client's code move into your normal dev setup. Even then, use client-owned accounts and least-privilege access.
# Disposable Node sandbox (Docker). No home-dir mount, no credentials, removed on exit.
docker run --rm -it --name sandbox -v "$PWD":/work -w /work node:22-bookworm bash
#   inside the container:
cat package.json                       # read scripts FIRST
ls -la .vscode .devcontainer 2>/dev/null
npm ci --ignore-scripts                # or: npm install --ignore-scripts
npm audit --omit=dev

# VS Code user settings (Cmd/Ctrl+Shift+P → "Preferences: Open User Settings (JSON)")
"task.allowAutomaticTasks": "off",
"security.workspace.trust.enabled": true
Hard rule. No legitimate interview or client needs you to paste a command into your terminal to "fix" your camera, run their code on your laptop before a contract, or turn off your security software. Any one of these ends the conversation.

4. Payment scams: overpayment, fake cheques, refunds, "pay to start", crypto#

How it looks: "We've sent ₹2L by mistake instead of ₹20k, please refund the difference." A cheque or screenshot for more than the invoice. "Buy the laptop/software from our approved vendor and we'll reimburse you." "Pay a ₹2,000 onboarding/verification fee." "We pay only in USDT; send your wallet."

Red flags: any flow where you send money. Payment "screenshots" instead of money in your account. Payment from a person or company that isn't the client named on the contract. Urgency plus a large number.

Prevention:

  • Money flows one way: client → you, against your invoice, from the contracting entity's own account. Check that it has actually cleared in your bank or payment-rail dashboard, not in a screenshot.
  • Never refund an "overpayment". Tell them to reverse it through their bank. Real mistakes get reversed by banks; scams disappear.
  • Don't accept crypto as payment for client work. It's irreversible, it complicates tax and FEMA reporting, and it's the payment method of choice for the scams above.
  • Never pay a fee to get work. Marketplaces' own Connects and memberships are the only exception.

If it happens: stop all transfers. Call 1930 and file at cybercrime.gov.in as fast as you can, because fast reports help banks block the money. Tell your bank. Keep chats, UPI/transaction IDs and screenshots.

5. Telegram/WhatsApp "task" job scams (India)#

How it looks: a WhatsApp message or Telegram group offering "part-time work from home": like YouTube videos, rate hotels, review products, "₹3,000–8,000/day". The first tasks pay small amounts (₹150–500) to build trust. Then come "prepaid tasks" or "merchant tasks" where you deposit money to unlock bigger payouts. The balance in their dashboard grows, but withdrawals are blocked until you pay "tax", "unfreeze" or "VIP" fees. Indian police and news reports describe individual losses from a few lakh to over ₹1 crore. Pune's cyber cell alone has reported crores in task-fraud losses.

Red flags: unsolicited job offers on WhatsApp/Telegram. Payouts for trivial tasks. Any request to deposit money. Dashboards that show "earnings" you can't withdraw. Group members cheering about payouts (they're part of the scam).

Prevention: real clients pay you for software work. They never ask you to deposit money. Block and report the number. Report suspicious messages through Sanchar Saathi → Chakshu (for suspected fraud communication, before any money is lost).

If money is lost: call 1930 right away and file at cybercrime.gov.in. Speed matters for freezing the money trail.

6. Marketplace scams: off-platform requests, fake support, account rental#

  • Off-platform: "Message me on Telegram/WhatsApp to discuss" before a contract exists. Upwork's terms keep you on the platform for 24 months unless the conversion fee is paid, and off-platform payment removes all your protection. Scam "clients" can still show "payment verified". → Reply on-platform only. Escrow must be funded before work starts.
  • Fake support: emails or DMs "from Upwork/Payoneer" asking you to log in through a link, verify your ID or share an OTP. → Go to the site directly. Never share OTPs. Turn on 2FA everywhere.
  • Account rental / "partnership": "We'll pay you ₹X/month to use your verified Upwork/LinkedIn/GitHub account" or "just attend interviews as the face". This is how fraudulent IT-worker schemes launder identity. It can get you banned and criminally exposed. → Always no.
  • Malicious "briefs": ZIP/EXE/.scr attachments or "Brief.pdf.exe". → Never open executables. View documents in the browser or Google Drive preview.

7. ID-document and bank phishing (Aadhaar, PAN, bank, OTP)#

  • Aadhaar: share a masked Aadhaar (only the last 4 digits visible, downloadable from myAadhaar) for identity checks. Full-number KYC belongs only on regulated platforms (bank, payment rail), entered by you on their official site.
  • PAN: Indian clients legitimately need it for TDS, but only after a contract is signed. Watermark copies: "For TDS by {{CLIENT_NAME}} only, {{DATE}}".
  • Never share OTPs, UPI PINs, net-banking logins, or screen-share while logged into banking. No real client needs them.
  • "KYC for payment release" links in WhatsApp/SMS are phishing. Real payment rails ask for KYC inside their own app or dashboard.
  • Check your credit report (CIBIL or Experian) twice a year for loans you didn't take.

8. Free "test" labour, scope creep and non-payment#

How it looks: "Build this feature as a test. If it's good, we'll hire you" (and the feature ships in their product). "Just a small change" ten times over. The final 50% that never arrives after handover. "We'll pay when our client pays us."

Prevention, built into this OS:

  • Paid first steps instead of free tests: A1 Essential, the B1 audit, the B3 assessment (Sales). A ≤ 60-minute exercise on their hosted platform during an interview is normal. A multi-hour feature on your machine isn't.
  • Contract + deposit = start. 50/50 (40/40/20 above ₹2L or $5k), Net 7, late fee, kill fee, IP transfers only on full payment, and a stop-work clause (Payment terms, Contracts).
  • Written scope with an "out of scope" list, and every change goes through a change request with a price (change-request.md, scope-creep-responses.md).
  • Hand over credentials and code ownership after the final payment, not before. Work on client-owned repos/stores, but keep the deploy keys and final transfer for the end.

If they don't pay: follow the payment-reminder ladder (friendly → firm → final notice → stop work). For Indian B2B clients, if you're Udyam-registered, the MSMED Act's 45-day rule and the MSME Samadhaan portal give you statutory interest and a dispute route (Udyam). On marketplaces, use the platform's dispute process. Small amounts: weigh time against money and write it off with a lesson learned. Big amounts: a lawyer's notice works more often than you'd expect.

9. Client concentration: the quiet risk#

Your first good client will want all your time, and it will feel safe. It isn't. When one client is most of your income, they set your rates, your hours and your mood. When they leave (a budget cut, a new CTO, an acquisition) your income goes to zero overnight and your pipeline is empty because you stopped marketing.

  • Rule: no client above 50% of trailing-6-month revenue. Aim for 40% once you have 3+ clients.
  • Keep marketing while busy: 3–4 hours a week minimum (one LinkedIn post, 10 personal touches, one referral ask), even at 100% utilisation.
  • Retainers spread risk: three ₹30–45k care plans are safer than one ₹1.2L client.
  • Long full-time contracts (6+ months, 40 hrs/week, their tools, their hours) are effectively a job without benefits. Price them that way: no discount for "stability", and keep a 30-day notice clause.

10. Payment-rail freezes and the mule-account trap#

  • Freezes happen on PayPal, Payoneer, Wise and others: a KYC mismatch, a sudden large payment, an unusual country, or a name on the account that doesn't match your PAN or bank. → Keep two working rails (Payment rails), withdraw to your bank regularly, and keep invoice + contract PDFs ready to answer compliance questions within a day.
  • Mule-account risk (India): bank accounts that receive money traced to cyber fraud can be frozen after a complaint on the national cybercrime portal. Innocent recipients get caught too, and unfreezing can take weeks and a lawyer. → Accept payment only from the contracting client's own account. Refuse "my friend/cousin will pay", P2P crypto-to-UPI sellers, and payments larger than the invoice.
  • Paper trail: every inward payment should match an invoice (amount, payer, purpose code/FIRA for foreign money). That's what gets a freeze lifted quickly.

11. Your previous employer: NDA, non-solicit, confidentiality#

Your strongest early leads are people you worked with at Noovosoft and on the Deribit and Twinntax engagements. Before you contact any of them about paid work, read your Noovosoft papers: offer and appointment letter, any NDA or IP agreement, the client-specific NDAs you signed, and the relieving letter.

12. IP contamination between clients#

  • One client = one repo, one folder, one browser profile. Never copy code from client A's repo into client B's.
  • Pre-existing IP: keep your own reusable snippets and starters in a personal repo, written on your own time, and list them in the contract as "pre-existing materials" licensed to the client (see the clause library in Contracts).
  • AI tools: tell clients which AI coding tools you use and how. Don't paste their secrets or customer data into AI tools. See ai-usage-policy.md.
  • Leaving a project: delete local copies of client code and data at the end (the handover checklist records this).

14. Client data and India's DPDP Act#

India's Digital Personal Data Protection Rules were notified on 13 November 2025, with a phased rollout over 18 months. Most substantive obligations apply from May 2027, and penalties go up to ₹250 crore for failing to take reasonable security safeguards. Those obligations fall on your client (the data fiduciary), and they will pass them on to you through the contract. EU/UK clients will ask you to sign a GDPR data-processing agreement.

  • Use client-owned accounts and least-privilege roles. Never use a shared admin login.
  • No production customer data on your laptop. Use staging with anonymised or seeded data. If you must touch prod, do it in their environment.
  • Turn on full-disk encryption (FileVault/BitLocker), a screen lock, and automatic OS updates.
  • Use a password manager and 2FA (authenticator app or hardware key) on email, GitHub, cloud, Shopify and payment rails.
  • If you suspect a breach, tell the client the same day in writing. They have notification duties.
  • At project end, delete exports, dumps and .env files, and record it in the handover checklist.

15. Credential and secret leaks#

GitGuardian found about 23.8 million new hardcoded secrets in public GitHub commits in 2024, up 25% on the year before. 70% of secrets leaked in 2022 were still valid two years later. AI-assisted coding has made this worse. One leaked Shopify admin token, Razorpay key or Supabase service-role key can end a client relationship.

  • .env* in .gitignore from the first commit. Add a pre-commit secret scanner (gitleaks or trufflehog) and turn on GitHub push protection.
  • Never put Supabase service-role keys or Razorpay secret keys in client-side code. This is also the #1 finding in B1 audits, so it doubles as a sales talking point.
  • Share credentials only through a password manager's shared vault. Never on WhatsApp, Slack or email. Policy: credentials-and-access-policy.md.
  • At offboarding, ask the client to rotate every key you had access to. Write it in the handover so it actually happens.

16. Burnout, isolation and the feast–famine cycle#

You've gone from a team, a salary and a schedule to working alone with no income yet. The most common failure isn't a scam. It's quitting at month 3 out of exhaustion and anxiety, just before the pipeline starts paying off.

  • Fixed hours: for example 9:30–6:30 IST with a hard stop. Global-client overlap is 2–3 hours, not all night.
  • Separate "maker" and "seller" time: outreach in the morning block, deep work after (daily schedule).
  • Runway visibility lowers anxiety. Know exactly how many months you have (Rate, Tax & Runway calculator) and set a bridge-income trigger in advance (contingencies).
  • People: one coworking day a week in Pune, one meetup a month, an accountability buddy (another freelancer) for a weekly 20-minute check-in.
  • Body: health insurance is now your own responsibility (safety net). Sleep, exercise and actual days off are business assets.
  • Warning signs: dreading the inbox, working weekends for weeks, saying yes to bad-fit clients out of fear. Then fix the system (pricing, pipeline, boundaries), not just your willpower.

17. Client red-flag scorecard (use before every "yes")#

Tick everything that applies. Any item in the first group = stop. Three or more in the second group = decline, or require 100% upfront for a small paid first step.

Stop immediately#

  • Asks me to run their code, installer or a terminal "fix" on my machine before a contract
  • Asks me to pay anything (fee, equipment, training, "verification") or refund an overpayment
  • Wants to pay in crypto, or from a third party's account
  • Pushes to move off the marketplace before a contract
  • Asks for OTPs, bank logins, full Aadhaar, or to "rent" my accounts
  • Won't put scope, price and terms in writing

Serious warning signs#

  • Company can't be verified (no website history, no LinkedIn presence, brand-new domain)
  • Rate or budget far above market for the work, plus urgency
  • Free "test task" over 1 hour, or "do this feature first, then we'll talk"
  • "Pay after launch / after funding / after our client pays"
  • Third developer on the project; bad-mouths all the previous ones
  • Changes scope repeatedly before signing
  • Unreachable decision-maker; everything goes through an intermediary
  • Demands constant availability (nights, weekends, WhatsApp at 11 pm)
  • Asks for non-compete or IP terms covering work outside the project

18. Incident playbook: what to do in the first hour#

SituationDo this now
You ran something suspicious1) Disconnect the machine from the network. 2) From a different, clean device, change your email password first, then GitHub, npm, cloud consoles, Shopify/Razorpay/Supabase, password manager. Revoke tokens and SSH keys, and sign out of all sessions. 3) Move any crypto to a new wallet created on a clean device. 4) Tell clients whose credentials were on the machine, the same day. 5) Wipe and reinstall the OS. Don't "clean" it. 6) Report at cybercrime.gov.in. CERT-In also accepts incident reports (cert-in.org.in).
You lost moneyCall 1930 immediately (the fastest way to freeze the trail), then file at cybercrime.gov.in with transaction IDs and screenshots. Call your bank's fraud line.
Suspicious message, nothing lostDon't engage. Report it on Sanchar Saathi → Chakshu, then block. Warn your network if they're impersonating someone you know.
Your bank account got frozenAsk the bank in writing for the reason and the complaint/FIR reference. Gather invoices, contracts and the payer's details. Consult a lawyer. Don't try to move funds around.
Client data exposed through youContain it (revoke and rotate), tell the client in writing the same day with facts and a timeline, help them meet their own notification duties, and write a post-mortem.
Legal notice from an ex-employerDon't reply in anger and don't ignore it. Pause the relevant outreach, collect your documents, and get a lawyer's view before responding.

19. Actions this week#

  • Set "task.allowAutomaticTasks": "off" in VS Code and Cursor. Confirm Workspace Trust is on.
  • Create a disposable sandbox (a VM snapshot or the Docker one-liner above) and test it once.
  • Move any crypto wallets and seed phrases off your work laptop.
  • Turn on 2FA everywhere and move all passwords into a password manager. Use a separate browser profile for client work.
  • Download your masked Aadhaar. Make a watermarked PAN copy template.
  • Find and read your Noovosoft offer letter, NDAs and relieving letter. Note any non-solicit period.
  • Write a short agreement with your Cultus co-founders about freelance work and conflicts.
  • Set up a second payment rail (Payment rails).
  • Save 1930 and cybercrime.gov.in in your phone.
  • Install gitleaks as a global pre-commit hook.
  • Book your weekly accountability call and one Pune meetup this month.
