A common trick against developers is a "test task" that steals your passwords and keys. The rule is simple: unknown code runs in a sealed box, never on your main laptop. This page shows the box, step by step.

How the trick looks

A "recruiter" from a crypto start-up messages you on LinkedIn. The pay is $80 an hour, well above normal. Before the call, they send a GitHub link:

"Please clone this repo, run npm install and fix the bug on the login page. Our CTO wants to see it in 2 hours."

The repository is a "React and Node dashboard" with three commits from a 2-week-old account. Inside package.json is a postinstall script with a long scrambled line. The moment you run npm install, that line downloads hidden software.

That hidden software looks for .env files, saved browser logins, crypto wallets and secure-login keys for servers (SSH keys). It sends them to the attacker within minutes.

This is real and still running. Microsoft described the campaign in March 2026. It has targeted developers since at least December 2022, and it now poses as freelance clients too: "can you fix our repo?"

As a JavaScript developer looking for work, you are exactly who it aims at. With one client's keys stolen, you could lose that client and your name.

The sealed box, step by step

A sealed box is a separate computer inside your computer. It holds no passwords, no keys and none of your files. If the code is bad, it only harms the box.

The best box is a throwaway container or a virtual machine (VM). A separate user account on your laptop is the bare minimum, and weaker.

  1. Read the code in the browser first, on GitHub or GitLab. Check the account's age, the number of commits and the stars.
  2. Open package.json and read the scripts section. Look hard at preinstall, install, postinstall and prepare.
  3. Look for the folders .vscode, .devcontainer and .husky. Read any tasks.json inside.
  4. Search for warning signs: eval, new Function, child_process, curl | sh, or long scrambled text.
  5. Start a throwaway container in that folder, with the command below. It does not see your home folder.
  6. Inside the box, install without running any scripts: npm ci --ignore-scripts.
  7. Run npm audit and look at what was installed.
  8. For the first run, cut the network if you can. Otherwise watch for connections to sites you do not know.
  9. When you finish, close the container. It deletes itself.
# Throwaway Node box. No home folder, no keys. Deleted on exit.
docker run --rm -it --name sandbox -v "$PWD":/work -w /work node:22-bookworm bash
# inside the box:
cat package.json
ls -la .vscode .devcontainer 2>/dev/null
npm ci --ignore-scripts
npm audit --omit=dev

If you use a VM instead (VirtualBox on Windows or Mac, Multipass on Linux), take a snapshot first. Roll back to it when you are done.

Two editor settings to change today

The trick can also start when you simply open a folder in your editor. A file called .vscode/tasks.json with "runOn": "folderOpen" runs code the moment the folder opens.

In Visual Studio Code or Cursor, press Ctrl+Shift+P and choose "Preferences: Open User Settings (JSON)". Add these two lines:

"task.allowAutomaticTasks": "off",
"security.workspace.trust.enabled": true

Now unknown folders open in "Restricted Mode". When the editor asks "Do you trust the authors?", choose No for any stranger's code.

Warning signs

  • A crypto, Web3 or AI company, a rate far above normal, and hurry.
  • A new GitHub or Bitbucket account, or one big "initial" commit.
  • Install steps that are oddly long, or scripts with scrambled text.
  • A meeting link that needs a special app or a "driver fix".
  • "Your camera is broken, paste this command to fix it."
  • Any request to turn off your antivirus or "trust the authors".

No honest client needs you to run their code on your laptop before a contract. No honest call needs you to paste a command into your terminal. Either one ends the talk.

A short coding test on the client's own website is normal. So is code you get after a contract starts on Upwork. Still read the scripts first, even then.

If you already ran it

Assume everything on that laptop is stolen. Work fast, in this order:

  1. Turn off Wi-Fi or pull the network cable on that laptop.
  2. On a different, clean device, change your email password first.
  3. Then change GitHub, npm, cloud, Supabase, Shopify and Razorpay passwords. Sign out of all sessions.
  4. Delete old access tokens and SSH keys, and make new ones later on a clean machine.
  5. If you keep crypto, move it to a new wallet created on a clean device.
  6. Tell any client whose keys were on that laptop, the same day, in writing.
  7. Wipe the laptop and reinstall the operating system. Do not try to "clean" it.
  8. Report it at cybercrime.gov.in. If money was taken, call 1930 as well.

Do this now

  • Add the two editor settings in Visual Studio Code and Cursor.
  • Install Docker and run the throwaway box once on a harmless project.
  • Move any crypto wallets and recovery words off your work laptop.
  • Use a password manager and two-step login on email, GitHub and npm.
